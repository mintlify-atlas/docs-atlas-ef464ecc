title: "Get started with KWCode and run your first task"
description: "Install KWCode, connect it to a local or cloud model, point it at your project, and run your first coding task through the expert pipeline."
---

This guide walks you from a fresh install to running your first coding task. The whole process takes about five minutes if you already have a local model running (e.g., Ollama with `qwen3:8b`) or a cloud API key.

## Steps

<Steps>
  <Step title="Install KWCode">
    Install KWCode from PyPI:

    ```bash
    pip install kwcode
    ```

    If you are in China or seeing slow speeds, use the Tsinghua mirror:

    ```bash
    pip install kwcode -i https://pypi.tuna.tsinghua.edu.cn/simple
    ```
  </Step>

  <Step title="Launch the REPL">
    Start the interactive session:

    ```bash
    kwcode
    ```

    On first launch, KWCode runs a brief onboarding flow. It detects your network environment, asks for your API base URL, API key (leave blank for local models), and model name, then verifies the connection before saving to `~/.kwcode/config.yaml`. You cannot skip this step — the configuration must be saved before the REPL opens.
  </Step>

  <Step title="Connect to a model">
    During onboarding you enter your connection details. You can also update them at any time inside the REPL with the `/api` command:

    ```
    # Connect to a local Ollama instance (no API key needed)
    > /api default http://localhost:11434

    # Connect to DeepSeek cloud API
    > /api default https://api.deepseek.com your-api-key

    # View current configuration
    > /api show
    ```

    Use `/api temp` instead of `/api default` for a temporary switch that does not persist across sessions. Switch models separately with `/model <name>` (e.g. `/model qwen3:8b`).
  </Step>

  <Step title="Navigate to your project">
    Point KWCode at your codebase, then initialize a project rules file:

    ```
    > /cd /path/to/your/project
    > /init
    ```

    `/init` creates a `KWCODE.md` file in your project root. This file is where you define project-specific conventions — test framework, naming rules, which files to avoid, and so on. KWCode loads it on startup and injects the relevant sections based on the current task type.
  </Step>

  <Step title="Run your first task">
    Type a task description in plain text and press Enter:

    ```
    > fix the login validation bug in auth.py
    ```

    KWCode classifies the task, locates the relevant code, generates a patch, runs `pytest`, and reports back. If verification fails, the Debug Subagent captures runtime variable values and retries with that data.
  </Step>
</Steps>

## What happens when you run a task

Every task goes through the same fixed pipeline. Here is what each stage does:

```
Your input: "fix the login validation bug"
│
├─► Gate
│     Classifies the task type (bugfix / codegen / refactor / chat / etc.)
│     Matches domain knowledge from the expert registry
│     Routes to the correct pipeline path
│
├─► Locator
│     BM25 keyword retrieval — finds candidate files without calling the LLM
│     AST call graph expansion — traces hidden dependencies along the call chain
│     Returns a ranked list of relevant files and functions
│
├─► Generator
│     Reads the original file content
│     LLM generates only the modified sections (not a full rewrite)
│     Injects domain knowledge from matching SKILL.md files
│
├─► Verifier
│     Applies the generated patch
│     Runs syntax check + pytest automatically
│     On success: done. On failure: triggers retry with Debugger.
│
└─► Debugger (on failure)
      LLM decides which line to instrument and which variables to inspect
      sys.settrace captures real variable values non-invasively
      Runtime data is injected into the next Generator retry
      Up to 3 retry rounds with reflection between each attempt
```

The Reviewer runs after a successful patch to confirm the change actually addresses what was requested.

## Example tasks

These are realistic examples you can try directly in the REPL after pointing KWCode at a project:

```
# Bug fix
> fix the KeyError when user has no profile set

# Code generation
> add a FastAPI endpoint POST /users/{id}/reset-password with JWT auth

# Refactoring
> split the calculate_price function into smaller functions

# Multi-task parallel execution
> /multi add docstrings to add_user ; add docstrings to remove_user ; add docstrings to update_user

# Multi-task with dependency chain
> /multi refactor extract_data function -> write tests for the refactored function
```
